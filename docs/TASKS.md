# Task Queue — Sibway Logistics

> Формується в Project-чаті (PM-роль). Claude Code бере в роботу лише
> перше завдання зі статусом `TODO`, зверху вниз. Не змінювати порядок
> без узгодження з PM. Формат кожного завдання — нижче. Синхронізовано
> з `sibway_project_final_artifacts.md` (backlog, розділ 10) станом на
> 2026-09-15.

## Як користуватись цим файлом

1. PM (Project-чат) формулює завдання і додає його в кінець списку
   зі статусом `TODO`.
2. Claude Code перед початком роботи читає `docs/CLAUDE.md`,
   `docs/RULES.md` і релевантні джерела істини (`docs/DECISIONS.md`,
   `docs/PROJECT_FACTS.md` тощо) — так само, як і раніше.
3. Claude Code бере **перше зверху** завдання зі статусом `TODO`,
   міняє статус на `IN PROGRESS`, виконує план → QA → чекає дозволу
   власника на commit/push, як завжди.
4. Після виконання: статус → `DONE`, додається короткий підсумок
   (файли, commit SHA, дата). Завдання не видаляється — лишається як
   історія, доки PM не почистить файл.
5. Якщо завдання заблоковане (бракує рішення власника, дані тощо) —
   статус `BLOCKED` + причина. Claude Code переходить до наступного
   `TODO`.

## Формат завдання

```
### [ID] Коротка назва

- Статус: TODO | IN PROGRESS | BLOCKED | DONE
- Додано: YYYY-MM-DD
- Контекст: сторінка/функція/проблема, репозиторій
- Бізнес-ціль: навіщо це потрібно
- Технічна ціль: що саме зробити
- Дозволений scope: точні файли/каталоги
- Заборони: що не чіпати
- Критерії приймання: перевірювані умови
- Перевірки: які QA-кроки виконати
```
