# Робочий процес та відповідальності

## Мета

Документ визначає, як команда Sibway Logistics планує, дизайнує, розробляє, перевіряє та приймає сторінки сайту.

## Принцип роботи

- **GitHub** — джерело правди для затверджених макетів, контенту, бренд-матеріалів, правил, документації, задач і перевірених версій коду.
- **Stitch** — створює дизайн-макети. До production-розробки допускаються лише матеріали з `design/approved/<page>/`, затверджені власником продукту.
- **Antigravity** — єдиний виконавець локальної production-розробки: пише, редагує, запускає і тестує код.
- **Perplexity** — Project Manager: формує вимоги, перевіряє готовність джерел, готує завдання для Antigravity, веде приймання та документацію. Perplexity не пише і не пушить production-код.
- **GitHub Pages** — preview-середовище для перевірених версій перед основним хостингом; не є щоденним середовищем розробки.

## Ролі

### Власник продукту

- Визначає бізнес-цілі, пріоритети, бюджет і фінально затверджує дизайн, тексти та результат.
- Погоджує зміни, які впливають на обсяг, структуру, бренд, контакти або реліз.

### Perplexity — Project Manager

- Не пише production-код і не підміняє Antigravity як виконавця розробки.
- Планує обсяг робіт, етапи, залежності, пріоритети і критерії готовності.
- Координує комунікацію, фіксує правки та підтримує документацію GitHub актуальною.
- Контролює відповідність результату затвердженим макетам Stitch, контенту та правилам проекту.
- Виявляє ризики: неповний контент, суперечливі контакти, відсутній макет, конфлікти Git, незавершені SEO або локалізація.
- Готує завдання для Stitch і Antigravity та проводить приймання результатів за критеріями готовності.
- Перед формуванням завдання уточнює доступні виконавцю інструменти, інтеграції, репозиторії, гілки та середовища.

### Stitch — дизайн і макети

- Створює дизайн-макети сторінок та їхні візуальні варіанти.
- Кожен макет проходить перегляд і затвердження власником продукту до передачі в розробку.
- Затверджені артефакти зберігаються в `design/approved/<page>/`, зокрема screenshot, HTML-прототип і README за потреби.
- Незатверджені макети не є джерелом для production-розробки.

### Antigravity — AI vibe coding і локальна розробка

- Пише, редагує та перевіряє код за затвердженими макетами Stitch, контентом і завданнями PM.
- Vibe coding: людина керує процесом природною мовою, формулює ціль, логіку й критерії результату; AI/LLM реалізує та виправляє код.
- Відповідає за актуальність локального коду, запуск, технічне тестування і виправлення помилок.
- Локально хостить поточну версію сайту. Поточна адреса розробки: `http://127.0.0.1:5173/`.
- Має доступ до GitHub через `github-mcp-server` і перед початком роботи зобов’язаний прочитати вказані PM джерела правди в репозиторії.
- Не підставляє власні тексти, цифри, контакти, кольори, зображення або іконки, якщо їх немає у затверджених джерелах. У разі суперечності або нестачі даних зупиняється й формулює конкретне питання.
- Після локальної перевірки готує перелік змінених файлів, скріншоти desktop/mobile, результат `npm run build` і список відкритих питань.
- Після PM-приймання зміни мають бути закомічені та відправлені до GitHub.

### GitHub — джерело правди

- Містить затверджені макети, контент, документацію та перевірені версії коду.
- Зміни, що мають зберігатися, повинні потрапляти в репозиторій із зрозумілим повідомленням коміту.
- Не додавати `node_modules`, `dist`, `.env`, локальні ключі, кеші або `.DS_Store`.
- Нові production-зміни не вносяться прямо в `main`: спочатку локальна перевірка, потім окрема гілка, PR і приймання.

## Доступ Antigravity до GitHub

Antigravity має доступ до репозиторію через `github-mcp-server`. У кожному завданні PM обов’язково вказує:

- повну адресу репозиторію;
- гілку або commit, з яких треба читати матеріали;
- повні шляхи до обов’язкових файлів;
- які джерела є пріоритетними у разі конфлікту;
- заборону на припущення та використання заглушок.

Стандартний блок для завдання Antigravity:

```md
## Джерела правди в GitHub

У тебе налаштований github-mcp-server. Перед початком роботи прочитай актуальні версії вказаних PM файлів у репозиторії: `https://github.com/Zsuff/sibway-logistics-website`.

Працюй лише із затвердженими макетами у `design/approved/`.
Не використовуй довільні контакти, числа, тексти, кольори, іконки або зображення.
Якщо дані в макеті, контенті чи правилах суперечать одне одному або чогось бракує — зупинися, сформулюй конкретне питання і не вигадуй заміну.
```

## Обов’язковий процес для кожної сторінки

1. PM формує вимоги: мета сторінки, аудиторія, маршрут, контент, CTA, SEO та критерії готовності.
2. PM перевіряє доступ Antigravity до GitHub MCP, локального проєкту, браузера, build-інструментів і потрібної гілки.
3. Stitch створює макет.
4. Власник продукту переглядає та затверджує макет.
5. Макет та його артефакти зберігаються у `design/approved/<page>/`.
6. PM перевіряє готовність контенту у `content/{lang}/{lang}_{page}.md`, правила контактів, бренд-матеріали, SEO та маршрут.
7. PM формує завдання для Antigravity із повними GitHub-шляхами до джерел правди.
8. Antigravity читає вказані матеріали через GitHub MCP та реалізує сторінку локально.
9. Antigravity запускає сайт локально, виконує перевірку desktop/mobile, навігації, CTA, форм і `npm run build`.
10. PM проводить приймання: порівняння з макетом, контентом, маршрутом, локалізацією, правилами контактів і Definition of Done.
11. Після схвалення Antigravity комітить зміни в окрему гілку, створюється PR, а після остаточного погодження зміни потрапляють у `main`.
12. GitHub Pages використовується для preview лише після локального приймання.

## Definition of Done

Сторінка вважається готовою, якщо:

- є затверджений макет Stitch у `design/approved/<page>/`;
- є повний контент UA, а для запланованих мов — EN і PL;
- Antigravity прочитав зазначені PM джерела через GitHub MCP;
- маршрут, header, footer, CTA і посилання працюють;
- дизайн відповідає затвердженому макету на desktop і mobile;
- застосовано `docs/CONTACTS_USAGE.md`;
- немає вигаданих контактів, цифр, текстів, кольорів або UI-елементів;
- є необхідні SEO-метадані, canonical та hreflang за планом;
- локальна версія перевірена в Antigravity, `npm run build` проходить без помилок;
- PM провів приймання;
- код і пов’язані артефакти закомічені в GitHub через окрему гілку та PR.

## Поточний цикл

- Затверджені макети: `homepage`, `services`.
- Код з Antigravity: React + Vite + TypeScript, локальна адреса `http://127.0.0.1:5173/`.
- Antigravity має GitHub-доступ через `github-mcp-server`.
- Поточний пріоритет: аудит і доведення реалізованих базових сторінок до макетів Stitch, актуального UA-контенту та правил контактів.
- Наступні сторінки: `transport`, `customs`, `warehouse`, `audit`, `about`, `contacts`, `privacy`, `terms`, `404` — у порядку «макет → затвердження → код → тестування → GitHub».
