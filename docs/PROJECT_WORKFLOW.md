# Робочий процес та відповідальності

## Мета

Документ визначає, як команда Sibway Logistics планує, дизайнує, розробляє, перевіряє та приймає сторінки сайту.

## Ролі

### Власник продукту

- Визначає бізнес-цілі, пріоритети, бюджет і фінально затверджує дизайн, тексти та результат.

### Perplexity — Project Manager

- Не пише production-код і не підміняє Antigravity як виконавця розробки.
- Планує обсяг робіт, етапи, залежності, пріоритети і критерії готовності.
- Координує комунікацію, фіксує правки та підтримує документацію GitHub актуальною.
- Контролює відповідність результату затвердженим макетам Stitch, контенту та правилам проекту.
- Виявляє ризики: неповний контент, суперечливі контакти, відсутній макет, конфлікти Git, незавершені SEO або локалізація.
- Готує завдання для Stitch і Antigravity та проводить приймання результатів за критеріями готовності.

### Stitch — дизайн і макети

- Створює дизайн-макети сторінок та їхні візуальні варіанти.
- Кожен макет проходить перегляд і затвердження власником продукту до передачі в розробку.
- Затверджені артефакти зберігаються в `design/approved/<page>/`, зокрема screenshot, HTML-прототип і README за потреби.
- Незатверджені макети не є джерелом для production-розробки.

### Antigravity — AI vibe coding і локальна розробка

- Пише, редагує та перевіряє код за затвердженими макетами Stitch, контентом і завданнями PM.
- Vibe coding: людина керує процесом природною мовою, формулює ціль, логіку й критерії результату; AI/LLM реалізує та виправляє код.
- Відповідає за актуальність локального коду, запуск, технічне тестування і виправлення помилок.
- Локально хостить поточну версію сайту. Поточна адреса розробки: `http://127.0.0.1:5173/`.
- Поточна реалізація містить 4 базові сторінки; подальші сторінки додаються лише після готового контенту та затвердженого макету.
- Після перевірки зміни мають бути закомічені та відправлені до GitHub.

### GitHub — джерело правди

- Містить затверджені макети, контент, документацію та код.
- Зміни, що мають зберігатися, повинні потрапляти в репозиторій із зрозумілим повідомленням коміту.
- Не додавати `node_modules`, `dist`, `.env`, локальні ключі або `.DS_Store`.

## Обов'язковий процес для кожної сторінки

1. PM формує вимоги: мета сторінки, аудиторія, маршрут, контент, CTA, SEO та критерії готовності.
2. Stitch створює макет.
3. Власник продукту переглядає та затверджує макет.
4. Макет та його артефакти зберігаються у `design/approved/<page>/`.
5. PM перевіряє готовність контенту у `content/{lang}/{lang}_{page}.md`.
6. Antigravity реалізує сторінку на основі затвердженого макету та актуального контенту.
7. Antigravity запускає сайт локально, виконує перевірку desktop/mobile, навігації, CTA та форм.
8. PM проводить приймання: порівняння з макетом, контентом, маршрутом, локалізацією і правилами контактів.
9. Після схвалення зміни потрапляють у GitHub з описовим commit message.

## Definition of Done

Сторінка вважається готовою, якщо:

- є затверджений макет Stitch;
- є повний контент UA, а для запланованих мов — EN і PL;
- маршрут, header, footer, CTA і посилання працюють;
- дизайн відповідає затвердженому макету на desktop і mobile;
- застосовано `docs/CONTACTS_USAGE.md`;
- є необхідні SEO-метадані, canonical та hreflang за планом;
- локальна версія перевірена в Antigravity;
- код і пов'язані артефакти закомічені в GitHub.

## Поточний цикл

- Затверджені макети: `homepage`, `services`.
- Код з Antigravity: React + Vite + TypeScript, локальна адреса `http://127.0.0.1:5173/`.
- Поточний пріоритет: аудит і доведення реалізованих базових сторінок до макетів Stitch, актуального UA-контенту та правил контактів.
- Наступні сторінки: `transport`, `customs`, `warehouse`, `audit`, `about`, `contacts`, `privacy`, `terms`, `404` — у порядку «макет → затвердження → код → тестування → GitHub».
