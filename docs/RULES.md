## Правила проекту Sibway Logistics

### Стек і технології

- Основний стек сайту: **React + Vite + TypeScript + CSS**.
- Використання React, Vite та TypeScript дозволено без додаткового погодження.
- Інші фреймворки/бібліотеки (Next.js, Vue, Nuxt, Tailwind, CMS тощо) — лише після окремого погодження.
- Для простих односторінкових лендінгів допускається варіант на чистому HTML/CSS/JS, якщо це явно обговорено.
- Зміни стеку (наприклад, перехід на Next.js або інший фреймворк) мають бути задокументовані в `CHANGELOG.md` і узгоджені.

### Контент і тексти

- Всі тексти сайту мають бути українською мовою.
- Не використовувати вигадані факти, цифри, відгуки, клієнтів, сертифікати без підтвердження.
- Контактні дані, адреса, телефон, email — тільки реальні, затверджені.

### Дизайн і стиль

- Дотримуватися затвердженого дизайну в Stitch як джерела істини.
- Зберігати кольори, шрифти, відступи, анімації згідно з макетами.
- Логотип у Header: ~40px desktop, 36px tablet, 32px mobile.
- Логотип у Footer: більший, ~160px width x 52px height (або пропорційно).
- У Footer не використовувати логотип (за вимогою) та іконки в навігації/контактах.

### Процес роботи зі сторінками

Для кожної нової або суттєво оновленої сторінки дотримуватися послідовності:

1. Створити або відредагувати макет у Stitch.
2. Перевірити й затвердити дизайн, структуру, контент та задум анімацій у Stitch.
3. Зберегти затверджений desktop-макет у GitHub:
   - PNG screenshot у `design/approved/<page>/`;
   - HTML-експорт Stitch у `design/approved/<page>/`;
   - README з маршрутом, Stitch Project ID, Screen ID і важливими дизайн-правилами.
4. Передати Antigravity Stitch Screen ID та маршрут сторінки.
5. Реалізувати сторінку в існуючому React + Vite + TypeScript проєкті, використовуючи спільні компоненти й стилі сайту.
6. Перевірити сторінку локально на desktop, tablet і mobile, а також усі маршрути, CTA та перехресні посилання.
7. Лише після затвердження локального результату зробити commit і push production-коду в GitHub.

Не створювати окремий React-проєкт для кожного макета. Усі сторінки реалізуються в одній кодовій базі сайту.

### Розробка і деплой

- Усі зміни спочатку тестуються локально.
- Після затвердження — коміт і пуш у GitHub для бекапу.
- Деплой на хостинг — тільки після окремого погодження.

### Робота з MCP / AI-агентами

- Використовувати Stitch для макетів та затвердження дизайну.
- Використовувати Antigravity для перенесення дизайну в код та локальної розробки.
- GitHub — для зберігання версій, документації та бекапу.
