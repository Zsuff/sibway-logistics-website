# Sibway Logistics — Інструкції для AI-агентів

## Контекст проекту

Sibway Logistics — українська B2B-компанія, що організовує міжнародну логістику. Основна спеціалізація — міжнародні автомобільні вантажні перевезення. За потреби компанія також може організувати морські, авіаційні та залізничні перевезення.

Перша версія сайту створюється українською мовою. Пізніше можуть бути додані польська, англійська, німецька та інші мови.

## Бізнес-напрями

Потенційні категорії послуг:

- збірні вантажі LTL;
- повні вантажі FTL;
- експрес-доставка малотоннажним транспортом;
- палетні та непалетні вантажі;
- сипучі вантажі;
- небезпечні вантажі ADR;
- вантажі з температурним режимом;
- негабаритні вантажі;
- внутрішні та міжнародні перевезення;
- мультимодальна організація доставки.

Не вважати цей список доказом доступності кожної послуги на кожному маршруті. Перед публікацією потрібне підтвердження фактичної можливості.

## Аудиторія та конверсія

Пишемо для бізнесу, власників і менеджерів з логістики, а не для приватних клієнтів. Основна дія — запит на розрахунок або консультацію. Додаткові дії — повідомлення, email і дзвінок.

## Правила коду

- Використовувати семантичний HTML5.
- Використовувати спільну CSS-систему та мінімальний vanilla JavaScript.
- Production-сайт має розгортатися завантаженням статичних файлів на shared hosting.
- Не додавати React, Next.js, Vue, Tailwind, Bootstrap, базу даних або npm-залежності без окремого погодження.
- Використовувати доступні landmarks, підписи полів, keyboard-friendly controls, видимий focus і корисні alt-тексти.
- Використовувати відносні посилання й перевіряти кожне посилання після змін.

## Перед редагуванням

1. Прочитати RULES.md, PROJECT_OVERVIEW.md, TODO.md та відповідні документи дизайну або SEO.
2. Назвати файли, які будуть змінені.
3. Описати очікуваний результат і спосіб перевірки.
4. Не змінювати затверджені рішення без прямого завдання.

## Після редагування

1. Відкрити змінені сторінки в браузері.
2. Перевірити мобільний і десктопний вигляд.
3. Перевірити посилання, зображення, форми, заголовки, метадані та console errors.
4. Повідомити, що саме змінено та що ще не перевірено.
5. Не оголошувати задачу виконаною лише на підставі згенерованого коду.

## Правила контенту

- Не вигадувати маршрути, ціни, терміни, сертифікати, кількість машин, клієнтів, відгуки або гарантії.
- Для відсутніх фактів використовувати `[ПОТРІБЕН КОНТЕНТ]`.
- Писати конкретно, стисло й корисно для B2B-клієнта.
- Уникати переспаму та дубльованих сторінок міст і країн.

## Правила Git

Приклади commit-повідомлень:

- docs: визначити початковий обсяг проекту
- feat: додати шаблон сторінки послуги
- fix: виправити мобільну навігацію
- seo: додати метадані та sitemap

Не додавати секрети або приватні дані клієнтів.
